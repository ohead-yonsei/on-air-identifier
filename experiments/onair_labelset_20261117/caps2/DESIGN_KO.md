# caps2 — 모자 분류기 보강 (설계)

2026-11-19 아침. `finish3/`에서 선두를 못 말하고 우승마를 틀리게 부르는 원인이 모자 번호 읽기(특히 7번, 10번, 11번 이상)로 드러났고, 사용자가 보강을 시작하라고 했다("네, 시작해줘"). 이 문서와 코드, 새 분류기를 **새 날의 화면을 처리하기 전에** 잠근다(`DESIGN_LOCK.sha256`).

## 무엇을 바꿨나

모자 분류기(ResNet-18, 1~11번, 11은 11번 이상)만 다시 학습했다. 기수 검출, 앞선 말 고르기 모델, 선두 모델, 말하는 규칙은 그대로다.

**새 라벨은 사람 손 없이 모았다.**

| 출처 | 방법 | 라벨 수 |
|---|---|---|
| 공식 기록 (`code/h2_mine_caps_official.py`) | 공식 통과 시각이 알려 주는 전 출전마의 순서와, 분류기가 확실히(0.9 이상) 읽은 기수들의 화면 위치를 맞춘다. 공식 순서로 두 기준 기수 사이(또는 맨 앞)에 말이 정확히 하나 있고 화면에서도 그 자리에 다른 기수가 정확히 하나 있으면, 그 기수에 그 번호를 붙인다. 개발용 6일과 측정용 3일 | 472 |
| 순위 띠 (`code/h1_mine_caps.py`) | 띠의 1~4위 가운데 셋을 확실히 읽었고 나머지 하나의 자리에 기수가 하나 있을 때. 6일 | 73 |

- 합계 545장: 7번 92장, 10번 39장, 11번 이상 50장(직접 붙인 598장에서는 54, 41, 38장).
- 분류기가 못 읽거나 틀리게 읽은 그림만 모이는 방식이다. 10번과 11번 이상의 57장을 Claude가 눈으로 봤고, 대부분 맞고 열에 한두 장은 틀려 보였다. 그래서 새 라벨은 "10%는 틀릴 수 있다"는 손실로 학습했다(`code/h3_train_caps.py`, 나머지 설정은 지금 분류기와 같음).
- 식별기는 실행할 때 띠도 공식 기록도 읽지 않는다. 둘은 학습 라벨을 만드는 데만 썼다.

## 새 날

**2026-08-15, 2026-08-09** (`otherday16`, `otherday17`). 재생목록에서 8월 16일보다 앞선, 한 번도 쓰지 않은 가장 최근의 10개 경주짜리 서울 경마일 2일(8월 17일은 11개 경주라 규칙에서 빠짐). 내용을 보기 전에 정한다(`DAYS_LOCK.sha256`).

## 실행과 채점

`run_test.sh`: 영상 받기 → 공식 성적표와 화면 시계 → 지금 분류기로 화면 처리(`g4_dense_whole.py`, `g10_dense_last.py`) → 같은 기수 상자에 새 분류기의 확률 계산(`h4_reprob.py`) → `h5_eval_caps.py` 한 번.

지표의 뜻과 계산은 고르는 단계와 같다. 정답은 공식 통과 시각으로 계산한 순서, 주 분석은 화면 시계가 공식 기록과 맞는 경주, 구간은 경주 단위 다시 뽑기 2000번(씨앗 20261118).

## 미리 정한 판정 (2일 합계)

| 판정 | 조건 |
|---|---|
| C1 선두의 번호를 더 자주 확정한다 | "확정된 시점"의 새 − 지금 차이에서 95% 구간 아래 끝이 0보다 크다 |
| C2 선두를 더 맞게 말한다 | "맞게 말한 시점" 차이의 구간 아래 끝이 0보다 크고, "틀리게 말한 시점"이 2.0%p 넘게 높지 않다 |
| C3 번호 문장을 해치지 않는다 | A와 B가 각각 지금 분류기보다 1.0%p 넘게 낮지 않다 |
| C4 약한 모자에서 나아진다 | 실제 선두가 7·10·11번 이상인 시점에서 "확정된 시점" 차이의 구간 아래 끝이 0보다 크다 |
| **새 분류기가 낫다** | C1, C2, C3가 모두 참 |

우승마 부르기(부른 수, 맞은 수)는 판정 없이 두 분류기를 나란히 적는다. 선두용 번호 확정 기준 0.4와 함께 쓴 값도 적는다.

## 한계 (미리 적는다)

- 2일, 20개 경주다. C4는 해당 시점이 적어(고르는 단계에서 5일에 158개) 구간이 넓을 것이다.
- 새 라벨은 "다른 기수들을 확실히 읽은 화면"에서만 나온다. 여러 기수를 한꺼번에 못 읽는 먼 화면의 예는 거의 없다.
- 새 라벨의 열에 하나쯤은 틀렸을 것이다. 눈으로 본 것은 57장뿐이다.
- 모자 그림은 기수 상자의 위쪽 35%이고, 헬멧보다 옷이 크게 잡힌 그림이 많다. 이 입력 방식은 바꾸지 않았다.
- 앞선 말 고르기 모델과 선두 모델은 지금 분류기의 확률로 학습한 것이다. 새 분류기에 맞춰 다시 학습하지 않았다.
- 이 시험은 같은 화면 자료 위의 계산이다. 통과하면 프로그램의 분류기를 바꾸고 출력이 계산과 같은지 따로 확인한다. 기본값을 바꿀지는 사용자가 정한다.
