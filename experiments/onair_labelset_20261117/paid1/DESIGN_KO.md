# paid1: 유료 모델(GPT-6.1 Terra)로 "화면만 본 모델" 기준선 재기 — 설계 (결과를 보기 전에 고정)

2026-11-21 작성.

## 왜

벤치마크 v0의 "화면만 본 모델" 기준선은 로컬 Qwen 3.5 9B이고 무작위 수준이었다. 팀의 다른 보고서에서 GPT-6.1 Terra는 순위 자막을 가린 화면에서도 순위를 잘 읽는 것으로 나왔다. 같은 모델을 우리 문항과 채점기로 재서, 강한 모델 기준선이 어디쯤인지 본다.

2026-11-21 사용자 결정: "유료 외부 API는 쓰지 않는다"는 규칙은 그대로 둔다. 이 측정은 그 규칙 밖의 따로 하는 시험이다(사용자가 넣어 둔 OpenAI 키, 충전해 둔 10달러 안에서, 먼저 경주 3~4개만). 식별기와 벤치마크의 우리 흐름에는 유료 모델이 들어가지 않는다.

## 무엇을 돌리나

- 모델: `gpt-6.1-terra` (OpenAI API, Chat Completions). 온도 등은 API의 기본값. 응답은 `{"line": "..."}` 형식으로 받는다.
- 입력, 경주 정보, 지시문 두 가지(`free` = 누가 앞서 있는지 중계하라, `careful` = 확실할 때만 번호를 말하라)는 `baseline_vlm.py`와 글자까지 같다. 그림 3장은 띠를 가린 1920×1080 그림 그대로, `detail: high`.
- 코드: `benchmark/v0/baseline_openai.py`.
- 대상: 시험용 경주 가운데 띠 문항과 띠 없는 문항이 모두 있는 43개에서, 씨앗 20261121로 4개를 뽑았다(결과를 보지 않고): **20260905_R09, 20260912_R08, 20260919_R04, 20261003_R08**. 문항은 113개(띠 61 + 띠 없음 52).
- 순서: (1) 모델 이름이 API에 있는지 확인. (2) 개발용 경주 하나(20261010_R02)의 3문항으로 형식과 문항당 비용 확인. 이 3문항은 채점하지 않는다. 형식 오류가 나면 호출 형식만 고치고(지시문과 입력은 그대로) 다시 한다. (3) 시험용 113문항을 `free`로 한 번, `careful`로 한 번. 다시 돌리지 않는다. 호출 오류로 답이 없는 문항만 한 번 더 시도한다.
- 돈: 실행마다 3달러에서 멈춘다(센 토큰으로 계산, 입력 100만 토큰 1달러, 출력 5달러로 가정). 전체는 10달러 안.

## 채점

- `code/pd1_score.py`: 같은 113문항에서 이미 저장된 기준선(번호 없음, 무작위, Qwen 두 가지, 식별기 v9, v11)과 나란히. 대표 지표(선두를 맞게 / 틀리게 / 말하지 않음), 틀린 문장 비율, A, B, 문항당 번호 수. 띠 문항과 띠 없는 문항을 따로도 낸다. 호출 시간과 비용도 적는다.
- 판정 기준은 두지 않는다. 경주 4개는 작아서 크기를 보는 용도다. 구간(신뢰 범위)은 내지 않는다.

## 읽을 때 조심할 것 (미리 적어 둠)

- 4개 경주, 113문항이다. 경주마다 차이가 크다.
- 문항은 3초 간격의 따로 떨어진 순간이고, 모델은 앞 순간을 모른다. 이어서 중계하는 팀 보고서의 조건과 다르다.
- 팀 보고서는 OpenRouter를 거쳤고 이 측정은 OpenAI에 직접 보낸다. 같은 이름의 모델이지만 설정이 같다는 보장은 없다.
- 채점기는 "N번 선두"처럼 조사가 없는 꼴을 선두 주장으로 읽지 못한다. 그런 문장이 얼마나 되는지 세어서 함께 적는다.
- 식별기 v11의 줄은 4개 경주 가운데 20260919_R04, 20261003_R08이 v11 분류기의 라벨에 쓰인 날이다.
