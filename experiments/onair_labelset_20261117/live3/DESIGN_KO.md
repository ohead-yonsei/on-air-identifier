# live3: 실시간 자막에 결승 구간 선두 모델 넣기 — 설계 (2026-11-23, 결과를 보기 전에 고정)

## 왜

live2(`live2/RESULT_KO.md`)에서 실시간 자막의 "선두는 N번" 문장이 안 쓴 날에 58.7%로 기준(75%) 미달이었다. 틀린 17개 중 12개가 결승 36~12초 전이었고, 모두 실제 2·3위 말을 선두라고 했다. 이 구간은 공식 통과 기록으로 학습한 결승 구간 선두 모델(`finish2/models/fs_leader_all.joblib`, v10의 선두 부분)이 새 날에서 선두 문장을 고친 구간이다. 이 모델을 실시간 묶음에 넣으면 선두 문장이 나아지는지 안 쓴 날에서 잰다.

## 무엇을 바꿨나

`identifier/live_run.py --finish-leader`(기본은 꺼짐). 실행 중에는 결승 시각을 모르므로 거리로 어림한 결승 시각(`expected_seconds`, 결승 직선 그림을 미리 돌릴 때 이미 쓰는 값)의 36초 전부터 선두를 결승 구간 모델로 정한다(그림 3장 중 2장, 아니면 앞 두 시점이 같을 때 이어받기 — v10과 같은 규칙). 번호, 순서, 우승마 부르기는 그대로다.

## 무엇을 돌리나

- **A**: `live_run.py --no-video`(live2와 같은 프로그램). **B**: `live_run.py --no-video --finish-leader`. 같은 경주마다 A, B를 차례로 실제 속도로 돌린다.
- 날: **2026-11-22, 2026-11-21 서울**(각 11경주, `otherday24`, `otherday25`). 채널 목록에서 "한 번도 쓰지 않은 가장 최근 서울 경마일 둘"이라는 규칙으로 내용을 보기 전에 골랐다. 지금까지 11경주 날은 쓰지 않았고(11/8은 11경주 하나만 시연에 씀), 이 두 날은 식별기의 학습과 선택에 쓴 적 없다. 받지 못한 영상은 뺀다.
- 출전표와 공식 기록은 `code/ls1_racecard.py`로 받는다(공식 기록은 채점에만).
- 참고(판정 밖): 이미 본 날인 2026-07-12에 B만 돌린다(live2의 A와 나란히 볼 용도).

## 채점과 판정

경주마다 `code/lv1_score.py`, 합치기는 `code/lv4_pool.py`. 두 쪽 모두 시계가 공식 기록과 맞는 경주(live2와 같은 규칙)만 판정에 넣는다.

| | 조건 |
|---|---|
| V1 개선 | B의 선두 맞음 비율이 A보다 5%p 이상 높고, B의 틀린 선두 수가 A보다 적다 |
| V2 기준 | B의 선두 맞음 75% 이상 |
| V3 다른 것은 그대로 | B의 번호 맞음 90% 이상, 지연 가운데값 0.5초 이하, 경주마다 가장 긴 지연 2.0초 이하, 결승 문장 3.0초 안 |
| V4 live2 재현 | A의 번호 맞음 90% 이상과 같은 속도 조건 |

V1과 V3을 채우면 `--finish-leader`를 실시간 묶음의 기본값으로 권한다. 경주를 다시 뽑은 부트스트랩 95% 구간(B − A)과 결승 36초 안의 선두 문장 값은 판정 없이 적는다.

1. 두 날 영상 받기가 끝날 때까지 기다린다(`live3/download.log`의 "download done").
