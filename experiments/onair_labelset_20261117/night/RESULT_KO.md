# 밤 실험 (2026-11-18) — 결과

사용자 요청("5~6시간 더 해볼 수 있는 연구나 개선")으로 밤사이 한 일이다. 설계, 채점 코드, 판정 기준은 새 날의 결과를 보기 전에 잠갔다([DESIGN_KO.md](DESIGN_KO.md), `DESIGN_LOCK.sha256`, `EVENTS.jsonl`). 판정은 잠근 그대로 적는다.

## 결론

1. **지금 구성(L1)은 새 날 나흘에서도 목표를 채웠다.** 말한 번호 939개 중 893개(95.1%)가 상위 3두였고, 579개 시점 중 499개(86.2%)에서 맞는 번호를 하나 이상 말했다. 하루씩 봐도 나흘 모두 A 90%, B 80%를 넘었다. 다만 B는 앞의 이틀(94.6%)보다 8%p 낮다. "앞의 이틀이 쉬운 날이었다"는 걱정은 맞았고, 그래도 목표 위다.
2. **"선두는 N번"은 94%가 아니라 88%쯤으로 봐야 한다.** 새 나흘에서 284번 중 249번(87.7%)이 맞았다. 9월 5일 하루가 79.0%라 "하루씩 80% 이상" 기준에 못 미쳤다. 기준값을 0.5로 낮춘 규칙은 344번 중 301번(87.5%)으로 정확도가 같고 더 자주 말했으며, 하루씩 기준도 채웠다. **선두 기준값은 0.5를 권한다.**
3. **"a번이 b번보다 앞"은 다시 나왔다.** 336번 중 307번(91.4%), 하루씩 모두 85% 이상.
4. **Qwen 없이도 된다.** 기수마다 Qwen에게 모자색을 묻는 단계를 빼도(F1) A 94.3%, B 87.6%로 L1과 차이가 없었고, 같은 경주에서 시점당 8.3초가 2.3초로 줄었다.
5. **아무 말도 못 하던 시점을 메울 수 있다.** L1이 아무 번호도 말하지 못한 시점에만 번호 하나를 더하는 규칙(L1s)이 B를 86.2%에서 91.0%로 올렸다. A는 0.5%p 내려갔다(95.1% → 94.6%).
6. **띠로 배우는 날을 늘려도 나아지지 않았다.** 나흘 대신 엿새로 배운 모델은 차이가 없었다.
7. **순서를 넣은 중계 시연:** "선두는 N번"이라고 말한 문장 42개 중 41개가 띠의 1위와 같았고, "뒤따른다"고 말한 문장 27개는 모두 맞았다.

위 2, 4, 5를 한데 묶은 구성(F2)은 프로그램에 넣었지만 **묶은 상태로는 새 날에서 확인하지 못했다.** 확인용 이틀의 영상을 받으려 할 때 유튜브가 로봇 확인을 요구해 멈췄다([confirm2/DESIGN_KO.md](confirm2/DESIGN_KO.md)).

## 프로그램에 넣은 것

`identifier/identify_l1.py`에 선택 사항 세 개를 더했다. 기본값은 그대로 L1이다.

| 선택 사항 | 뜻 |
|---|---|
| `--fast` | F1. 기수에 Qwen을 쓰지 않는다 |
| `--fallback` | 아무 말도 못 한 시점에 번호 하나를 더한다(L1s의 규칙) |
| `--leader-tau 0.5` | 선두 기준값 |

셋을 함께 쓰면 **F2**다. 프로그램의 F2 출력이 채점 스크립트의 계산과 같은지 이틀(9/19, 9/5)로 확인했다(`check/*_f2_check.txt`, 아래 표).

| 확인 | 결과 |
|---|---|
| F2 프로그램 대 채점 스크립트, 9/19 (136개 시점) | 문장·선두·앞뒤·더한 번호 모두 136개 시점에서 같음 |
| F2 프로그램 대 채점 스크립트, 9/5 (143개 시점) | 모두 143개 시점에서 같음 |
| 선택 사항을 더한 뒤의 `--fast` (9/19) | 전과 같음 (136개 시점) |

**F2는 묶은 상태로 확인된 구성이 아니다.** 세 조각은 각각 위에서 확인됐지만, 함께 쓴 값은 이미 본 나흘에서 계산한 것뿐이다(탐색): A 93.9%(1011개 중 949개), B 90.7%(579개 중 525개), 선두 88.1%(353번 중 311번), 앞뒤 91.8%(355번 중 326번). 새 날 이틀(8/29, 8/23)에서 확인하는 설계를 잠가 두었으나, 영상을 받지 못해 채점하지 못했다.

대신 이미 받아 둔 2026-11-15(11개 경주, 띠가 있던 140개 시점)를 프로그램으로 다시 돌려 봤다. 이 날은 L1의 결과를 이미 본 날이고 미리 잠근 시험이 아니므로 **참고로만** 적는다(`code/nc5_score_day_programs.py`).

| 2026-11-15, 프로그램 출력 | A | B | 선두 | 앞뒤 | 시점당 |
|---|---|---|---|---|---|
| L1 (기본) | 97.0% (223/230) | 87.9% (123/140) | 44/46 | 67/73 | 10.4초 (띠 읽기 포함) |
| F1 (`--fast`) | 96.3% (234/243) | 91.4% (128/140) | 54/57 | 78/82 | 2.1초 |
| F2 (`--fast --fallback --leader-tau 0.5`) | 96.0% (237/247) | 93.6% (131/140) | 65/70 (92.9%) | 78/82 | 2.1초 |

F2가 메우기로 더한 번호는 4개였고 그중 3개가 맞았다. 아무 말도 못 한 시점은 L1 16개, F1 12개, F2 8개였다.

### 어떤 문장을 더 믿어도 되는가

식별기가 문장마다 함께 내는 신호가 실제로 맞는 정도와 얼마나 맞물리는지를 새 나흘에서 나눠 봤다(`code/nd1_confidence.py`, `confidence_new_days.json`). 이 나흘은 모델이 배우지 않은 날이고, 기준값은 하나도 고치지 않았다. L1 기준이다.

| 번호 문장이 나온 길 | 맞은 것 |
|---|---|
| 지금 그림 3장 모두에서 뽑힘 | 399개 중 394개 (98.7%) |
| 지금 그림 3장 중 2장에서 뽑힘 | 416개 중 381개 (91.6%) |
| 3초 전과 6초 전에서 이어받음 | 124개 중 118개 (95.2%) |
| 메우기: 3초 전 번호를 이어 말함 | 15개 중 14개 (93.3%) |
| 메우기: 가장 확실한 기수 한 명 | 24개 중 18개 (75.0%) |

| 그 밖의 신호 | 맞은 것 |
|---|---|
| "상위 3두일 확률" 0.9 이상인 번호 | 553개 중 547개 (98.9%) |
| 확률 0.6~0.9인 번호 | 262개 중 228개 (87.0%) |
| 번호를 둘 이상 말한 시점에서, 하나 이상 맞음 | 384개 중 383개 |
| 번호를 하나만 말한 시점 | 123개 중 116개 (94.3%) |
| 선두 문장(기준값 0.5), 점수 0.8 이상 | 151번 중 139번 (92.1%) |
| 선두 문장, 점수 0.5~0.8 | 142번 중 114번 (80.3%) |
| 선두 문장, 이어 말한 것 | 51번 중 48번 (94.1%) |

- 식별기의 확률은 실제 정확도와 같은 방향으로 움직인다. "3장 모두에서 뽑힘"이나 "확률 0.9 이상"은 거의 틀리지 않는다.
- 중계에서 쓸 수 있다. 예를 들어 강한 문장(3장 모두)은 단정해서 말하고, 약한 문장(2장, 메우기의 한 명)은 "~로 보입니다"로 말하게 할 수 있다. 이 나눔은 결과를 본 뒤에 한 것이므로 새 날에서 확인해야 한다.
- Qwen 없는 구성(F1)도 같은 모양이다(3장 모두 453개 중 445개, 2장 404개 중 360개).

### 시간이 어디서 드는가

빠른 구성(F2)으로 2026-11-15 3경주의 22개 시점을 돌리며 단계별로 쟀다(`code/nd2_timing.py`, `timing/R03_f2_breakdown.json`). 한 번 잰 대략의 값이다.

| 단계 | 시점당 |
|---|---|
| 영상 파일에서 그림 3장을 찾아 꺼내기 | 0.78초 |
| 기수 검출 (그림 3장) | 0.24초 |
| 나머지 전부 (모자 분류기, 작은 모델 둘, 투표) | 0.07초 |
| 합계 (모델 올리는 1.7초 제외) | 1.09초 |

- **계산은 시점당 0.3초다.** 나머지는 영상 파일에서 원하는 시각의 그림을 찾아가는 시간이다. 영상을 앞에서부터 차례로 풀면 초당 530장(60장짜리 영상의 9배 속도)이라, 실시간 방송을 받으면서 3초마다 한 번 말하는 데는 여유가 있다.
- 프로그램을 통째로 돌렸을 때의 2.3초에는 프로그램을 띄우고 닫는 시간이 들어 있다.
- 실제 방송 입력으로 돌려 본 것은 아니다.

### 묶은 구성(F2)으로 중계 시연

세 번째 실행과 규칙·프롬프트·세는 방법을 그대로 두고 식별기 출력만 F2로 바꿨다([DEMO_F2_KO.md](DEMO_F2_KO.md)에 미리 적음). 2026-11-15, 띠로 채점.

| | L1의 출력 (세 번째 실행) | F2의 출력 (네 번째 실행) |
|---|---|---|
| 선두 중계 시점 | 148 | 159 |
| 식별기가 선두를 준 시점 | 49 | 76 |
| "선두는 N번" 문장 (띠가 있던 시점) | 42개 중 41개 맞음 | 63개 중 59개 맞음 (틀린 4개는 모두 2위) |
| "N번이 뒤따른다" 문장 | 27개 중 27개 | 40개 중 40개 |
| 말한 번호 | 211개 중 204개 (96.7%) | 220개 중 210개 (95.5%) |
| 틀린 번호가 들어간 시점 | 7 | 10 |

- 선두를 말하는 문장이 1.5배로 늘었고(42 → 63), 맞는 비율은 97.6%에서 93.7%로 내려갔다. 더 자주 말하고 조금 더 틀리는 쪽이다.
- 틀린 선두 문장 4개 중 3개는 한 경주(6경주)에서 선두가 바뀌던 9초 동안 나왔다. 띠와 식별기가 서로 다른 순간에 바뀐 것으로 보이지만 확인하지 않았다.

## 이 결과가 뜻하는 것

- **조건 A·B는 여섯 날로 확인됐다.** 다만 날에 따라 B가 82~95%로 움직인다. "B 94.6%"는 대표값으로 쓰면 안 되고, 엿새 합계 89.0%가 더 믿을 만한 값이다.
- **순서는 "선두 88%, 앞뒤 91%"로 적어야 한다.** 틀린 선두는 거의 2위 말이라, 중계에서 치명적인 오류(없는 말을 부르는 것)는 아니다.
- **실시간에 가까워졌다.** Qwen을 빼면 계산은 시점당 0.3초다. 영상 파일에서 그림을 찾아 꺼내는 시간까지 넣어도 1초 남짓이다.
- **더 배울 것은 모자와 작은 기수다.** 날을 늘려도 앞선 말 고르기는 나아지지 않았다. 남은 오류는 멀리서 잡은 화면과 특정 모자색(보라, 분홍)에 몰려 있다.

## 한계

- 기준이 순위 띠다. 띠가 화면에 있는 구간만 쟀고, 띠는 화면보다 늦을 수 있다.
- 새 나흘은 모두 8~9월의 서울, 같은 채널이다. 9월 5일은 국제 트로피 경주일이다.
- 3초 간격의 시점은 서로 닮았다. 그래서 구간은 경주 단위로 냈다.
- 판정이 여러 개다. 여러 개를 한꺼번에 본 것에 대한 보정은 하지 않았다.
- 처리(받기와 검출)는 설계를 잠그기 전에 시작했다. 잠그기 전에는 새 날의 화면, 식별 결과, 채점을 보지 않았다(`EVENTS.jsonl`).
- 보완 규칙(L1h, L1s)은 이미 본 엿새의 오류를 나눠 본 뒤에 만든 것이다. 새 나흘의 값은 잠근 뒤에 잰 것이다.
- 속도는 한 경주에서 한두 번 잰 대략의 값이다.
- 중계 시연은 하루, 모델 하나, 프롬프트 한 가지다. 선두 문장은 정규식으로 찾았다. L1의 번호 문장은 이 날을 이미 채점한 적이 있다.
- F2는 새 날에서 확인하지 못했다.
