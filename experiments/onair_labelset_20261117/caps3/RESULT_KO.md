# caps3 — 라벨 수집 한 번 더, 순서 모델 다시 학습 (결과)

2026-11-19 오후. 설계는 [DESIGN_KO.md](DESIGN_KO.md)에 있고, 새 날의 영상을 받기 전에 설계·코드·모델·날짜를 잠갔다. 채점은 한 번 했다(`EVENTS.jsonl`). 비교 대상은 지금의 기본값 v11이다.

## 한눈에

1. **라벨 수집을 한 번 더 돌린 분류기(B)는 새 날에서 확인되지 않았다.** 해친 것은 없지만 얻은 것도 없었다. 선두를 맞게 말한 시점은 50.6%로 v11과 같았다.
2. **순서 모델을 다시 학습하면 선두를 조금 더 자주 말하지만, 틀린 말도 같이 는다.** 분류기 B와 함께 쓰면 선두를 맞게 말한 시점 50.6% → 53.5%, 틀리게 말한 시점 7.6% → 9.0%. 미리 정한 둘째 판정은 채웠지만 맞바꿈이다.
3. **기본값은 v11 그대로 둔다.** 프로그램도 바꾸지 않았다.

같은 방식으로 라벨을 더 모으는 길은 한 번으로 끝난 것으로 보인다. 다음에 더 올리려면 다른 종류의 자료(먼 화면의 모자, 사람이 확인한 라벨)나 다른 입력(헬멧만 잘라 보기)이 필요하다.

## 새 날에서의 결과

2026-08-08, 07-26(20개 경주, 시계가 맞는 16개 경주, 445개 시점). 같은 기수 상자에서 견줬다(`eval_test.txt`).

| | 선두 번호 확정 | 선두를 맞게 | 선두를 틀리게 | A | B | 우승마 |
|---|---|---|---|---|---|---|
| v11 (분류기 A + 지금 모델) | 73.5% | 50.6% | 7.6% | 91.3% | 88.3% | 13개를 불러 12개 |
| B (분류기 B + 지금 모델) | 74.8% | 50.6% | 6.7% | 92.3% | 87.9% | 15개를 불러 14개 |
| B+M (분류기 B + 다시 학습한 모델) | 74.8% | 53.5% | 9.0% | 91.7% | 89.7% | 17개를 불러 16개 |

| 판정 (잠근 그대로) | 조건 | 결과 |
|---|---|---|
| B가 v11보다 낫다 | 해치지 않고, 선두를 맞게 말한 시점 또는 B의 차이에서 구간 아래 끝이 0보다 큼 | **거짓.** 해친 것은 없음(틀린 선두 −0.9%p, A +1.0%p, B −0.4%p). 선두 +0.0%p(구간 −2.0 ~ +2.1), B −0.4%p(구간 −2.6 ~ +1.9) |
| B+M이 선두를 더 자주 맞게 말한다 | 선두를 맞게 말한 시점 차이의 아래 끝이 0보다 크고, 틀린 선두 +2.0%p 이내, A·B −1.0%p 이내 | **참.** +2.9%p(구간 +0.4 ~ +5.5). 틀린 선두 +1.4%p(구간 −0.5 ~ +3.2), A +0.4%p, B +1.4%p |

- B+M에서 말했을 때의 정확도는 86.9% → 85.6%로 조금 내려간다(v11은 259번 중 225번, B+M은 278번 중 238번).
- 우승마는 세 경우 모두 틀린 것이 하나씩이고 모두 2위 말이다. v11도 이 2일에서는 13개 중 12개였다.
- 결과를 본 뒤에 따로 본 것(탐색): 분류기는 A 그대로 두고 모델만 다시 학습한 A+M은 선두를 맞게 +2.2%p(구간 +0.7 ~ +3.8), 틀리게 +1.6%p(구간 +0.7 ~ +2.7)였다. **얻는 것은 모델을 다시 학습한 데서 나오고, 분류기 B의 몫은 거의 없다.**

## 고르는 단계 (이미 본 7일, 결론 아님)

라벨과 모델 학습에 쓰지 않은 7일, 52개 경주, 1,378개 시점(`eval_held.txt`).

| | 선두 번호 확정 | 선두를 맞게 / 틀리게 | A / B |
|---|---|---|---|
| v11 | 75.8% | 48.1% / 7.1% | 93.4% / 91.8% |
| B | 78.5% | 49.9% / 7.0% | 93.9% / 93.6% |
| A+M | 75.8% | 51.6% / 8.3% | 93.6% / 91.1% |
| B+M | 78.5% | 54.3% / 8.6% | 94.0% / 94.0% |

고르는 단계에서는 B+M이 선두 +6.2%p / 틀린 선두 +1.5%p로 좋아 보였는데, 새 날에서는 +2.9%p / +1.4%p였다. 이미 본 날에서의 값이 새 날에서 줄어드는 일이 이번에도 되풀이됐다.

## 무엇을 했나

- **라벨 수집 2회차.** v11의 분류기로 번호를 다시 읽힌 뒤 같은 방식(`code/h2_mine_caps_official.py --source A`, `h1_mine_caps.py --probs`)으로 336장을 더 모았다(공식 기록 279장, 띠 57장). 1회차의 545장보다 적다. 분류기가 이미 많이 읽게 됐기 때문이다.
- **2회차 라벨은 잡음이 더 많았다.** 50장을 눈으로 봤는데, 10번과 11번 이상은 대체로 맞았고, 분류기가 다른 번호를 강하게 확신한 그림은 열에 서너 장이 틀려 보였다(헬멧이 초록·검정·보라인데 1번이라고 붙은 것). 분류기가 맞고 라벨이 틀린 경우다. 남은 "못 읽는 기수"에는 정말 어려운 그림과 순서 계산이 어긋난 그림이 섞여 있다.
- **순서 모델 다시 학습.** 앞선 말 고르기 모델, 선두 모델, 결승 구간 선두 모델을 같은 날·정답·설정으로, 번호 확률만 새 분류기의 것으로 바꿔 학습했다(`code/h7_train_models.py`).

## 이 결과가 뜻하는 것

- **1회차의 큰 효과는 "분류기가 못 읽던 쉬운 그림"을 가르친 데서 나왔다.** 2회차에 남은 것은 어렵거나 라벨이 의심스러운 그림이어서 더 가르쳐도 나아지지 않았다.
- **순서 모델을 다시 학습하는 것은 기준을 조금 낮춘 것과 비슷하게 움직였다.** 더 말하고 더 틀린다. 새 날에서의 비율(맞게 +2.9 대 틀리게 +1.4)은 환각을 줄이려는 목적에는 받아들이기 애매하다.
- 선두의 번호가 확정되지 않는 시점은 새 날에서 여전히 26%쯤이다.
