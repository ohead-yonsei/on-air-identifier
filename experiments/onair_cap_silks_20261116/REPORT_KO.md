수동 영역을 사용해 **검출 실패와 식별 실패를 분리**했다. 처음 검수에서 일부 옷 영역에 바지·옆 기수 모자가 포함되어, 모델 호출 전에 옷 영역을 수정했다. 옷 영역과 겹치는 알려진 모자 사각형은 회색으로 가렸다. 원본 음성, 방송 순위 그래픽, 결과 화면, 안장 번호는 입력하지 않았다. 모자 원본 크기는 약 21~34픽셀 폭이며 확대는 정보를 새로 복원하는 작업이 아니다.

## 기존 색상 규칙 기준선

진행 공유 문서의 HSV 색 이름 분류·색 히스토그램·복색 점수 함수를 추출해 사용했다. 계수와 임계값을 이번 정답에 맞춰 수정하지 않았다. 모자 점수, 옷 점수, `0.6×모자 + 0.4×옷`을 비교하고, 점수 0.40 이상·1/2위 점수 차 0.08 이상일 때만 번호를 반환했다. 이 점수는 보정된 정답 확률이 아니다. 검출기·전역 일대일 배정까지 포함한 원래 v4 전체 성능 시험은 아니다.

| 규칙 입력 | 정답/전체 | 오답 | 보류 | CPU 계산 시간 중앙값 |
|---|---:|---:|---:|---:|
| 모자 | 3/6 (50.0%) | 3 | 0 | 0.285ms |
| 옷 | 1/6 (16.7%) | 3 | 2 | 0.424ms |
| 모자+옷 | 3/6 (50.0%) | 2 | 1 | 0.723ms |

이 시간은 메모리에 올라온 영역의 특징 계산과 분류만 잰 값이다. VLM 시간은 로컬 HTTP 요청과 모델 처리를 포함한다. 따라서 두 숫자로 전체 시스템 속도 배수를 계산하면 안 된다. 영상 디코딩·자동 검출·추적·크롭 생성 시간은 어느 쪽의 실시간 성능으로도 입증되지 않았다.

단순 색 규칙은 10번/11번을 5번으로, 흰 모자 1번을 3번으로 잘못 판단했다. 기존 색 구간·전경 처리의 한계를 보여주며, 학습형 모자 분류기의 한계로 일반화할 수 없다. 규칙의 줄무늬 처리는 색 조합 수준으로, 실제 줄무늬 형태를 학습한 것이 아니다.
