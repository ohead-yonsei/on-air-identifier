## 1. 입력과 카메라 전환

원본 영상에는 다음이 함께 들어 있었다.

- 초반의 두 카메라 동시 화면.
- 말 위에 번호·이름을 띄워 주는 이동형 방송 그래픽.
- 경주 후 클로즈업, 배당 표, 전환 애니메이션, 결승선 재생 화면.

핵심 8프레임 비교에서는 이런 구간을 제외했다. 좌상단 `(0,0)–(240,110)`과 하단 `y=610–720`을 마스킹하고 음성을 사용하지 않았다. 모델에 입력한 파일·해시·시각을 저장했다. 전체 조사용 이미지에는 분석을 위해 원래 추가 그래픽이 보이는 프레임도 보존했으며, 핵심 모델 입력과 구분한다.

프레임은 원본 컨테이너 PTS를 사용했다. 움직임 추정에는 현재 프레임과 **0.1초 또는 0.5초 전** 프레임만 사용했다. 공식 기록의 통과순위를 임의 시점의 순위 라벨로 쓰지 않았다.

## 3. 실제 자동 검출과 모자 입력 영역

설치된 torchvision의 `fasterrcnn_resnet50_fpn_v2`, `COCO_V1` 가중치를 **새 실험 전용 캐시**에 받았다. 실제 클래스 번호는 person=1, horse=19이다. 이 모델은 일반 말·사람 박스를 찾는 모델이며, 기수 모자·말 코끝 전용 검출기가 아니다. 일부 겹친 기수에는 중복 박스가 생겼다.

후속 진단은 다음과 같이 실행했다.

`말 박스 검출 → 방향으로 선두 후보 박스 선택 → 가까운 기수 후보 연결 → 기수 박스 상단 35% 추출 → 모자색 분류`

후보 선택에는 정답 좌표를 사용하지 않았다. 선택 후에만 수동 기준의 코끝·모자 중심이 포함됐는지 평가했다. 박스가 기준점을 포함한다는 것은 정확한 개체 분리나 완전한 모자 검출과 같은 뜻이 아니다.

| 방향 제공 방식 | 선택한 말 박스가 선두 초안 코끝 포함 | 자동 모자 후보 영역이 기준 모자 중심 포함 | 보라색 분류 | 분류 보류 |
|---|---:|---:|---:|---:|
| 수동 방향 | 8/8 | 8/8 | 3/8 | 3/8 |
| 9B 모델 추정 방향 | 2/8 | 2/8 | 1/8 | 5/8 |

수동 방향 조건에서도 2개는 보라색을 파랑으로 분류했다. 자동 후보 영역에는 모자 외에 파란 경주복·얼굴·주변 기수가 함께 들어갔다.

실패를 본 뒤, **같은 8프레임에서 모자만 수동으로 좁게 잘라** 동일 모델·동일 분류 프롬프트·동일 생성 설정으로 추가 호출했다. 이때는 8개 모두 보라색이었다. 이는 사후 입력 진단이며 모든 표본이 같은 보라색 모자다. 그래도 같은 프레임의 넓은 영역과 좁은 영역을 비교했으므로, 입력 영역의 영향은 확인할 수 있다.

![자동 후보 영역과 수동 모자 영역 비교](/Users/ohead/Documents/ChatGPT/ON-AIR_프로젝트/experiments/onair_overnight_20261116/highlights/02_roi_vs_tight_cap.jpg)

**우선 해야 할 일은 ‘모자색 분류 클래스 추가’보다 실제 모자를 포함하는 정확한 영역을 얻는 것이다.** 이후 모든 색·무늬를 포함한 검수 자료로 분류기를 비교해야 한다. 이번 8/8을 11개 마번 클래스의 정확도로 표현하지 않는다.

## 5. 카메라 움직임을 보정한 자동 방향 추정

현재·과거 프레임에서 특징점을 추적하고, 말·사람 박스 밖의 배경 움직임을 먼저 맞춘 뒤 말 박스 내부의 남은 움직임을 계산했다. 수동 방향·마번·정답 코끝 좌표는 추정에 사용하지 않았다.

최초 0.5초 간격의 homography 방식에서 방향 반전과 보류가 나왔다. 이후 시간 간격 0.1/0.5초 × 배경 보정 homography/partial affine의 네 조건을 **같은 8프레임에서 탐색**했다. 모든 결과를 보존했다.

| 조건 | 방향을 출력한 화면 | 보류 |
|---|---:|---:|
| 0.5초, homography | 5 | 3 |
| 0.5초, partial affine | 3 | 5 |
| 0.1초, homography | 8 | 0 |
| 0.1초, partial affine | 8 | 0 |

출력 개수가 많다는 것이 정확도가 높다는 뜻은 아니다. 0.1초 affine 방식은 두 입력 프레임과 검출 박스를 좌우 반전했을 때 **8/8에서 원래 벡터의 반전 방향과 15도 이내**로 일치했다. 이는 구현의 기하 일관성 검사이며 실제 주로 이동 방향의 정답 검증이 아니다.

여기서 중요한 한계가 드러났다. 처음 수동으로 준 방향은 화면에 보이는 자세를 바탕으로 정한 **휴리스틱 축**이지, 보정된 주로 이동 벡터가 아니다. 특히 정면·코너에서는 머리의 모양, 지면상 이동 방향, 순위 비교에 필요한 동일 진행거리선이 서로 다를 수 있다. 수동 축과 자동 벡터의 각도 차이는 자료로 남겼지만 이를 ‘방향 정확도’라고 계산하지 않았다. 결과를 보고 수동 축을 고쳐 점수를 올리지도 않았다.

자동 0.1초 방향으로 22개 수동 코끝을 화면상 단순 정렬했을 때, 선두 초안 9번과 일치한 화면은 **5/8**이었다. 37·48·52초에는 1번 대응 코끝을 선택했다. 일반 말 박스 중심을 정렬해도 같은 5/8이었다. 움직임 추정과 순위 좌표의 보정은 별도 문제라는 사례다.

## 7. 다음 우선순위

1. **모자 영역 확보:** 기수 박스 상단을 잘라 쓰는 현재 방식의 혼입·잘림부터 해결한다. 뷰·크기·겹침별 모자 박스를 검수하고, 모자 검출 또는 정확한 머리 영역 추출을 비교한다. 이번 입력 비교에서 가장 직접적인 근거가 나온 부분이다.
2. **같은 말–기수의 대응:** 코끝·머리·몸통·기수·모자 연결에 일대일 배정과 시간상 추적을 결합하되, 후보가 없으면 미배정할 수 있어야 한다. 이번 수동 좌표 22/22를 자동 시스템의 22/22로 옮겨 말하면 안 된다.
3. **뷰와 주로 위치:** 컷 감지 후에도 뷰를 계속 갱신한다. 카메라 이동 방향과 순위 좌표를 나누고, 정면·곡선 구간은 검수된 기준이나 주로 보정 없이 단순 x/y·직각선으로 확정하지 않는다.
4. **중계 연결:** 검증된 실황만 언어 모델에 전달하고, 식별·순위가 불확실한 상태를 명시적으로 내보내 배경 사실로 전환한다. 이번 밤에는 이 시각 단계와 fixed-fact 중계까지의 통합 성능을 새로 평가하지 않았다.

다음 한 가지 실험으로는 **서로 다른 경기·모자색·뷰를 포함한 검수 세트에서 ‘현재 기수 영역’과 ‘모자 전용 검출 영역’을 같은 분류기에 넣는 비교**를 권한다. 경기 단위로 개발·평가 자료를 나누고, 식별 오류·판단 보류·처리 시간을 함께 본다. 현재 자료만으로 특정 색 분류기나 뷰별 전용 모델의 전반적 우수성을 정할 수 없다.

## 8. 실패·한계·보존

- 새 사람 검수는 수행하지 못했다. 새 라벨은 모두 assistant 초안이며, 8개 선두 초안도 같은 9번이다. 다른 선두·다른 경주·후면 뷰는 검증하지 못했다.
- 자동 코끝 검출 모델을 학습하거나 검증하지 않았다. 연결 실험의 코끝 좌표는 수동 입력이다.
- 27B의 로컬 태그와 digest는 확인했지만, 외부 공식 배포 버전 이름까지 확인한 것은 아니다.
- 움직임 보정 코드 확장 중 시각화 좌표 변수와 명령행 인자 변수가 충돌해 두 CPU 실행이 중단됐다. 변수 이름만 고친 뒤 같은 설정으로 재실행했고, 실패 전 코드·오류·원래 실패 조건 결과를 보존했다. 모델 재시도는 없었다.
- 초기 흐름 설정 파일의 `foreground_corners_per_box=80` 표기는 코드의 실제 ‘말 박스 합집합에서 최대 800개 점’과 달랐다. 메타데이터 오류를 별도 정정 기록에 남겼으며 알고리즘 변경으로 처리하지 않았다.
