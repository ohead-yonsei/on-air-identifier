# 야간 연구 계획 — 2026-11-16 밤 ~ 11-17 오전 9시(KST)

## 핵심 질문

같은 영상·검출 결과를 사용할 때, 카메라 뷰와 진행 방향을 반영한 연결 규칙이 코끝–모자 오연결을 줄이는가? 자동 검출·방향 추정이 들어오면 그 효과가 유지되는가?

현재 근거는 같은 경기의 두 프레임과 수동 좌표다. 야간 연구에서는 새 시점·카메라 전환을 포함하고, 수동 좌표 연결의 결과와 자동 시스템의 결과를 분리한다. 영상 전체를 보더라도 미래 프레임·결과 그래픽을 해당 시점의 모델 입력이나 정답으로 사용하지 않는다.

## 순서와 완료 조건

1. **영상 조사:** 전체 영상의 실제 PTS, 컷 후보, 대표 프레임을 저장한다. assistant가 전환·실경주/재생 구간·뷰를 검토하고 새 평가 시점을 고정한다. 카메라 전환 감지 후보와 수동 확인을 구분한다.
2. **좌표 연결 비교:** 기존 35.0/38.5초는 규칙 개발 자료로 표시한다. 새 프레임의 코끝·모자 대응 초안을 별도로 기록하고, 알고리즘 실행 전에 파일 해시를 고정한다. A=거리, B=뷰 방향으로 뒤쪽 후보 제한, C=B+중복 금지, D=B+후보 거리 차에 따른 보류를 비교한다. D는 `(2위거리-1위거리)/max(1위거리,1) >= 0.10`을 미리 고정하고, 같은 평가 표본 결과에 맞춰 바꾸지 않는다. 누락·보류·오연결을 각각 기록한다.
3. **자동 처리 점검:** 기존 Qwen3.5:9b로 뷰·방향 판단과 선두 후보/코끝/모자 위치 출력을 독립 호출로 확인한다. 가능하면 설치된 torchvision의 공식 사전학습 말·사람 검출기를 프로젝트 전용 캐시에 받아, 몸통 검출의 실제 범위를 점검한다. 코끝/모자 전용으로 학습된 검출기로 표현하지 않는다. 패키지·서비스·기존 모델 설정은 바꾸지 않는다.
4. **근거 모음:** 의미 있는 성공·실패·불확실 사례의 원본 시점, 마스킹된 프레임, 입력, 출력, 판단 근거를 묶는다. 오전 보고서는 핵심 발견, 다음 우선순위, 사용자 검수가 필요한 항목, 미완료·실패를 포함한다.

## 비교와 해석

- 같은 입력 좌표를 A/B/C/D에 제공한다. 수동 방향에 의존한 결과는 자동 방향 추정의 성능으로 세지 않는다.
- 새로운 코끝 대응은 assistant 육안 초안이다. 기존 사용자 확인 라벨과 합쳐 전문가 정확도를 만들지 않는다.
- 동일 말·동일 경기의 여러 프레임은 독립 경기 표본이 아니다. 새 시점 평가도 다른 경기로의 일반화 검증은 아니다.
- 모델의 확신 표현·신뢰 점수는 실제 정확도로 사용하지 않는다.
- 모자색→번호 대응은 정적 정보다. 선두·순위는 별도의 동적 판단이다.
- 다른 모델 또는 전용 학습의 이득을 입증하려면 뷰별 검수 데이터가 더 필요하다. 오늘은 모델 규모 경쟁보다 입력·연결·뷰 처리의 병목을 찾는다.

## 실행 한도와 보존

모든 신규 코드·가중치 캐시·결과는 `onair_overnight_20261116` 아래에 저장한다. 초기 VLM 요청 상한은 실패 포함 160회, 검출 프레임 상한 240장, 공개 가중치 다운로드 상한 700MB다. 외부 유료 API/Jev는 사용하지 않는다. 첫 모델 호출을 확인한 뒤 묶음을 실행한다. 반복 실패·시간 한도·완료 시 종료하며 시간을 채우기 위한 반복은 하지 않는다.

서버 실행은 중단 후 이어갈 수 있게 JSONL에 호출 전 ledger와 호출 후 raw 결과를 기록한다. 장시간 배치가 필요하면 SSH 종료와 독립적인 세션으로 실행하고 PID·상태 파일을 남긴다. 실제 실행 여부를 확인하기 전에는 백그라운드 실행 중이라고 보고하지 않는다. 최종 보고서와 주요 이미지는 맥에도 복사한다.
