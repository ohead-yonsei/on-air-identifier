# 코끝–모자 연결 실제 진단 결과

2026-11-16, 사용자 서버 실행. 코드·설정·원시 결과는 이 보고서와 같은 실험 폴더에 보존했다.

## 먼저 답할 점

**코끝을 기준으로 선두 후보를 고르는 아이디어는 이 두 화면에서는 작동했다.** 수동 진행 방향과 코끝 좌표를 사용했을 때 두 화면 모두 기존 사용자 확인과 같은 선두 9번을 선택했고, 선두 코끝에서 가장 가까운 모자도 9번이었다. 다만 같은 경주의 같은 선두를 3.5초 간격으로 본 두 사례이며, 자동 검출이나 다른 선두를 맞힌 검증은 아니다.

**가까운 모자를 그대로 같은 말의 기수로 간주하는 규칙은 다른 말에서 오류가 났다.** 전체 11개 코끝 연결 중 4개는 육안 대응 초안과 달랐다. 이 오류는 뒤쪽 말들에서 발생했으므로, 이 사실만으로 ‘선두에만 적용하는 방법이 실패했다’고 주장할 수 없다. 다만 선두 후보를 잘못 선택하거나 혼전 구간의 여러 말을 처리할 때 필요한 대응 관계를 거리 하나로 보장하지 못한다는 실제 반례다.

## 말의 각도에 따라 선이 달라지는가?

현재 구현에서 방향은 **화면별 수동 값**이다. 35.0초에는 화면 왼쪽·아래 방향 `(-1, 0.5)`, 38.5초에는 화면 아래 방향 `(0, 1)`을 지정하고 정규화했다. 같은 화면의 모든 말에 같은 방향을 썼다. 말의 머리 각도, 카메라 자세, 주로 접선 방향을 자동으로 추정한 것은 아니다.

- **노란 기준선:** 해당 코끝을 지나며 화면 진행 방향에 수직인 선이다. 따라서 두 화면에서 기울기가 다르다.
- **초록 연결선:** 같은 말이라고 육안으로 추적한 코끝과 기수 모자를 잇는다. 두 점 위치에 따라 각도가 다르며, 순위를 비교하는 기준선이 아니다.
- **빨간 연결선:** 거리 규칙이 다른 말의 모자를 선택한 사례다.

말이 고개를 돌릴 때마다 순위 기준선을 그 머리 방향에 맞춰 돌리는 방식은 사용하지 않았다. 실제 순위 판정에는 주로 위의 진행 방향과 원근을 함께 다뤄야 한다. 이번 화면상 평행선은 주로 보정이나 높이가 다른 코끝의 3차원 위치를 반영한 등거리선이 아니며, 공식 도착 판정선도 아니다.

## 실제 입력과 검수 범위

| 항목 | 35.0초 | 38.5초 |
|---|---|---|
| 영상 시점 | 원본 PTS 35.0, decoded index 1049 | 원본 PTS 38.5, decoded index 1154 |
| 화면 | 측면에 가까운 비스듬한 화면 | 정면에 가까운 비스듬한 화면 |
| 평가 코끝 | 9·1·10·5·11번에 대응하는 5개 | 9·1·2·10·5·11번에 대응하는 6개 |
| 모자 후보 | 화면의 11개 모자 모두 | 화면의 11개 모자 모두 |
| 제외 | 2번 코끝은 겹침으로 명확히 분리하기 어려워 제외 | 선택한 6개 코끝 모두 사용 |
| 마번 검수 | 이번 표시의 번호는 assistant 초안 | 기존 사용자 확인 6개 번호를 사용 |

코끝은 원본 1280×720 프레임에서 수동으로 표시한 대략적인 주둥이 끝 위치다. 미세한 공식 코끝 경계나 사진판정 정답이 아니다. 모자 중심은 수동 박스 중심이다. 코끝–말 머리·목·몸통–기수의 대응은 assistant의 육안 검토 초안으로 기록했으며, 이 새 대응에 대한 사용자·전문가 확인은 아직 없다.

측면 2번 외의 나머지 후미 말 코끝은 추가 라벨링하지 않았다. 따라서 모자 후보는 11개이지만 평가 코끝은 5/6개인 부분 집합이다. 전체 출전마 검출률·전체 순위 정확도는 계산하지 않는다.

방송 음성은 전혀 사용하지 않았다. 원본은 그대로 보존했고, 결과 검토·시각화용 그림에서는 그래픽을 마스킹했다. 알고리즘에는 좌표만 들어간다. 화면상 순위 그래픽은 정답 구축 근거로 사용하지 않았다. 기존 사용자의 선두 9번 확인과 모자 6개 확인은 서로 별도 근거로 유지했다.

## 기본 규칙의 실제 결과

코끝·모자 입력 순서를 각각 섞었다. 아래 알고리즘에는 마번이나 정답 대응을 넘기지 않았다.

1. **가장 가까운 모자:** 코끝과 모자 중심의 2차원 유클리드 거리를 최소화한다. 한 모자가 여러 코끝에 선택될 수 있다.
2. **기준선에 가까운 모자:** 코끝을 지나는 진행 방향 수직선과 모자 사이의 수직 거리를 최소화한다. 사용자가 말한 ‘선과 가까운 모자’의 한 가지 단순 구현이며, 가능한 모든 선 기반 알고리즘을 대표하지 않는다.
3. **모자 중복 금지:** 모든 평가 코끝에 모자를 하나씩 배정하되 모자 재사용을 금지하고, 거리 합을 최소화한다. Hungarian 방식의 선형 할당을 사용했다.

다음 수치는 **육안 대응 초안과의 일치 수**이며 전문가 라벨 기반 정확도가 아니다.

| 규칙 | 측면 5개 | 정면 6개 | 총 11개 |
|---|---:|---:|---:|
| 가장 가까운 모자 | 3/5 | 4/6 | 7/11 |
| 기준선에 가까운 모자 | 1/5 | 1/6 | 2/11 |
| 모자 중복 금지 | 3/5 | 6/6 | 9/11 |

중복 금지는 정면의 오류를 해결했지만 측면에서는 11번 코끝을 5번 모자로, 5번 코끝을 7번 모자로 연결했다. 전체 최소 거리라는 조건만으로 같은 말의 기수를 보장하지 못했다. 육안으로 몸통을 따라 연결한 초안은 비교 기준으로만 사용했으며, 이를 자동 몸통 연결 모델의 ‘11/11’ 결과로 계산하지 않았다.

## 실패를 본 뒤 추가한 방향 제한 규칙

기본 거리 규칙의 4개 오연결은 모두 대상 코끝보다 화면 진행 방향 앞쪽에 위치한 모자를 선택했다. 이에 **진행 방향 기준으로 코끝 뒤쪽에 있는 모자만 후보로 남기고, 그중 가장 가까운 모자를 고르는 규칙**을 추가했다.

이 규칙은 실패를 확인한 **동일한 11개 표본에서 고안하고 확인한 사후 탐색**이다. 독립 검증 성능이 아니다. 원래 결과를 덮지 않고 `posthoc_direction/`에 분리했다.

| 후속 규칙 | 측면 | 정면 | 전체 |
|---|---:|---:|---:|
| 코끝 뒤쪽 후보만 허용 + 최소 거리 | 5/5 | 6/6 | 11/11 |

화면 방향을 각각 -30°, -15°, 0°, +15°, +30° 회전해도, 고정된 좌표에서 위 결과는 유지됐다. 이는 이 두 장의 대략적 방향 범위에 대한 확인일 뿐, 자동 각도 추정이나 다른 카메라·역방향에서 검증한 결과가 아니다.

좌표 오차에는 취약했다. 코끝 각 축에 균등 ±5px, 모자 중심 각 축에 균등 ±2px 오차를 독립적으로 더한 2,000회 진단에서 정면 5번 연결이 육안 기준과 일치한 비율은 **50.6%**, 정면 1번은 **67.4%**였다. 이것은 실제 검출기의 정확도나 확률 추정이 아닌 임의 오차 민감도 실험이다.

정면 5번 코끝에서 조건을 만족하는 모자는 5번까지 96.1054px, 1번까지 96.3133px로, 두 후보의 거리 차가 **0.2079px**밖에 안 된다. 따라서 원 좌표의 11/11만 보고 안정적으로 작동한다고 평가하면 안 된다. 프레임 해상도, 코끝·모자 검출 오차, 고개 움직임에 대한 여유가 부족하다.

## 속도와 실행 횟수

CPU: 실제 서버의 Intel Xeon Gold 6246R @ 3.40GHz. Python 3.12.3, NumPy 2.5.2, SciPy 1.18.0, Pillow 12.3.0. `OPENBLAS_NUM_THREADS=1`, `OMP_NUM_THREADS=1`로 실행했다.

| 규칙 | 측면 중앙값 | 정면 중앙값 |
|---|---:|---:|
| 가장 가까운 모자 | 0.0079ms | 0.0085ms |
| 기준선에 가까운 모자 | 0.0083ms | 0.0090ms |
| 모자 중복 금지 | 0.0096ms | 0.0106ms |
| 뒤쪽 후보 제한 | 0.0199ms | 0.0206ms |

각 값은 **한 화면의 5/6개 코끝과 11개 모자를 연결하는 좌표 계산**을 1,000회 측정한 중앙값이다. 코끝·몸통·모자 검출, 영상 디코딩, 사람 또는 assistant의 표시 시간, 모자색 분류, 추적, 파일 I/O를 포함하지 않는다. 전체 시스템의 프레임당 지연이나 이전 VLM 호출 속도와 직접 비교할 수 없다.

실제 고유 입력은 두 프레임이다. 기본 결과는 11개 × 3규칙 = 33개 연결, 후속 방향 탐색은 11개 × 5각도 = 55개 연결이다. 시간 측정 및 좌표 흔들림 반복은 새 장면이나 독립 표본으로 세지 않았다. 모델 생성 0회, 학습 0회, GPU 추론 0회. 실행 실패와 재시도 없음.

## 검증·보존

- 기존 프레임 두 장의 SHA256을 실행 기록에 남겼다. 원본 영상·기존 실험·실행 환경은 변경하지 않았다.
- 마스킹 및 세 규칙의 좌표 순서 불변성 확인 8개를 통과했다.
- 원시 비용 행렬, 입력 좌표 배열 순서, 예측 인덱스, 1,000회 시간 측정값을 JSONL로 저장했다.
- 코끝·모자 좌표, 수동 방향, 임시 대응, 사용자 라벨 범위를 분리해 기록했다.
- 기본 결과 이후 방향 제한 규칙을 추가했다는 순서를 파일과 보고서에 명시했다.

## 해석과 다음 실험

이번 실험에서 확인한 것은 **좌표를 주어도 같은 말과 모자를 연결하는 문제가 남는다**는 점이다. 기하 계산 시간은 작지만, 자동 검출의 시간과 오류는 아직 측정하지 않았다. 코끝을 앞뒤 기준으로 쓰는 아이디어와 모자를 신원 단서로 쓰는 아이디어는 함께 유지할 수 있다. 그 사이에 같은 말의 머리·몸통·기수를 연결하는 근거가 필요하다.

다음 한 가지 실험은 **현재 프레임을 제외한 카메라 전환 전후 장면에서, 코끝→말 몸통→기수→모자 대응을 평가하는 것**이다. 겹침·정면·측면을 포함한 별도 프레임에 대응 관계를 사용자 검수하고, 이번 방향 제한 기준과 몸통 연결을 쓰는 방법을 같은 입력에서 비교한다. 검출 누락, 다른 말과의 연결, 모자색 오분류를 각각 나눠 집계해야 한다. 이것이 확인되기 전에는 전체 순위나 중계 정확도 개선을 주장하지 않는다.
